Does the panel work on new data?

The 7 genes were chosen using GSE48350. Accuracy measured on those same samples is too optimistic, because the genes were picked to fit them. So the panel was tested on a dataset it had never seen: GSE5281, from a different study and lab.

How the test was done

  1. Downloaded the GSE5281 series matrix from NCBI GEO and kept the hippocampus samples.
  2. Found each gene’s probes on the Affymetrix HG-U133 Plus 2.0 chip. LINC03007 and LINC02987 have newer names than the chip annotation, so they were matched by NCBI Gene ID (646588 and 101927151).
  3. Converted the MAS5 values to log2 and standardised each gene within the dataset. The GSE48350 means could not be reused, because this data is on a different scale.
  4. Scored every sample without looking at the labels, then compared scores with labels.
  5. Changed nothing about the panel after seeing the results.

Script: validation/validate_gse5281.py, plain Python with no extra packages. It runs in about a second after the 36 MB download.

What could explain it

Overfitting

The genes were picked from about 20,000 using only 37 samples. With that many candidates, some will separate a small dataset by chance.

Batch effects

In GSE48350, disease status and processing batch overlap, so some “Alzheimer’s” genes may really be batch genes.

Different material

GSE5281 used laser-captured CA1 neurons, while GSE48350 used whole tissue. This makes the test harder, but a robust marker should still point the same way.

Small test set

23 samples gives a wide interval, but even its upper end ({{ "%.2f"|format(v.auc_ci95[1]) }}) is close to chance.
